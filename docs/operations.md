# Эксплуатация локального стенда

**Назначение документа.** Краткий runbook для демонстрационной и технической команды: публикация, проверка, откат и типовые инциденты.

## Публикация

1. Зафиксируйте commit SHA и сохраните текущий `.env` вне репозитория.
2. Запустите `docker compose build` и затем `docker compose up -d`.
3. Дождитесь health контейнеров командой `docker compose ps`.
4. Проверьте четыре HTTP health endpoint и smoke-сценарий студента/преподавателя.
5. Перед демонстрацией не обновляйте модели и образы без повторной smoke-проверки.

## Откат

Код откатывается запуском ранее проверенного commit/tag и пересборкой контейнеров. Миграции не имеют down-скриптов: откат кода допустим только если старая версия совместима с уже применённой схемой. Данные volume не удаляйте. Перед рискованной миграцией нужен `pg_dump`; проект пока не предоставляет готовый скрипт.

## Проверка работоспособности

| Слой | Проверка | Признак нормы |
| --- | --- | --- |
| Web | `http://localhost:5173` | открывается вход |
| API | `/api/v1/health` | `status=ok` |
| Ready | `/api/v1/ready` | database не `down` |
| STT | `:8090/health` | `stt=ready` |
| LLM | `:8091/health` | `status=ready`, ожидаемая model/provider |
| TTS | `:8092/health` | status движка ready |
| Postgres | `docker compose ps` | container healthy |

## Наблюдаемость

Реализованы stdout/stderr контейнеров, Nest Logger, Python logging, health endpoints и отображение latency probe в админ-интерфейсе. Централизованных логов, метрик Prometheus, distributed tracing и alerting нет. Проценты «доступности» в UI — моментальный расчёт числа отмеченных сервисов, не SLI за период.

Логи:

```powershell
docker compose logs --tail=200 api stt llama llm tts web postgres
docker compose logs -f llm
```

## Backup и восстановление

API раз в час проверяет наличие snapshot за текущую UTC-дату и создаёт ежедневный JSON-файл; ручной snapshot доступен через админку. По умолчанию путь внутри API — `data/backups`. В compose этот каталог не смонтирован в volume, поэтому файлы могут исчезнуть при пересоздании контейнера. JSON неполный и автоматического restore нет. Для сохранности PostgreSQL используйте отдельный проверенный `pg_dump` и тест восстановления до эксплуатации.

## Инциденты

### UI не открывается

Проверьте контейнер `web`, порт `5173`, затем логи Nginx. Если API отдельно здоров, проблема в web build/proxy.

### Вход не работает

Проверьте `/api/v1/ready`, миграцию `0002_app.sql` и наличие пользователей в Postgres. Локальный клиентский fallback может маскировать отказ API; сравните поведение после очистки данных сайта только на тестовой машине.

### Нет распознавания

Проверьте разрешение микрофона, `/health` STT, наличие T-one model files и WebSocket `/ws/stt`. Ошибка `model_not_ready` означает проблему модели, а не браузера.

### Нет ответа заявителя

Проверьте LLM health, затем `llama` и объём свободной RAM. Убедитесь, что provider/model совпадает с ожидаемым: локальный `.env` может переключить провайдера.

### Нет звука

Проверьте TTS health и browser autoplay. Если текстовая реплика есть, можно продолжать демонстрацию без звука и зафиксировать деградацию.

### Преподаватель не видит студента

Проверьте `/api/v1/training/live`, сетевой proxy и свежесть `updatedAt`. Наличие Socket.IO соединения само по себе не подтверждает live presence, потому что этот поток идёт по REST.
