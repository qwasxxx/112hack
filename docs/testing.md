# Проверка качества

**Назначение документа.** Показать разработчикам и проверяющим, какие автоматические и ручные проверки существуют и что фактически было запущено.

## Команды

```powershell
pnpm build
pnpm --filter @sys112/student-web test
apps\llm\.venv\Scripts\python.exe -m pytest apps/llm/tests -q
apps\stt\.venv\Scripts\python.exe -m pytest apps/stt/tests -q
apps\tts\.venv\Scripts\python.exe -m pytest apps/tts/tests -q
```

Python-команды требуют предварительного запуска соответствующего `scripts/start-*.ps1`, который создаёт venv. TTS-тесты могут загружать модель или зависеть от аудиосреды; сначала прочитайте конкретный тест.

## Что покрыто тестами

- LLM: история и изоляция сессий, отбрасывание дублей, обработка think, mock WebSocket, анализ, вмешательство преподавателя, генерация билетов и защита темы.
- STT: PCM-конвертация, mock-сессия, partial/final стабилизация, health и reconnect WebSocket.
- Student Web: разбор STT-сообщений, downsample, состояния звонка, ошибки микрофона, вызов LLM только по final.
- TTS: mixer/ambient, эмоциональные сценарии и скорость Silero; эти тесты более тяжёлые.

## Ручная приёмка

Для релизного демо обязательна буквальная smoke-проверка из [development.md](development.md). Дополнительно проверьте отказ каждого голосового сервиса: TTS должен дать текстовую деградацию, а STT/LLM — понятное сообщение без зависшего интерфейса. Не считать сценарий пройденным без записи даты, машины, commit SHA и фактического результата.

Ролевую приёмку следует проводить по [user-flows.md](user-flows.md): отдельно пройти основной и альтернативные пути студента, преподавателя и администратора. Проверяющий фиксирует фактический экран, действие, ожидаемый переход, результат и созданную запись данных.
